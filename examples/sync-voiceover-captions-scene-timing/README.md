# Sync voiceover, captions and scene timing

Build one ten-second video from a reviewed timing record. The example keeps narration and word captions on the project timeline, converts a visual cue to each scene's local clock, and accounts for two 0.4-second crossfades.

Article: https://zvid.io/blog/tutorials/sync-voiceover-captions-scene-timing

## Requirements and cost

- Node.js 22 or newer, with npm.
- A Zvid account and an API key from https://app.zvid.io/api-keys.
- Render credits for the current estimate. The default maximum is 10 credits. `npm start` validates and estimates without submitting a render or consuming render credits. `npm run render` spends credits after validation succeeds.

The sample narration is already hosted at a public Zvid CDN URL in `data/timing.json`. No speech generation or transcription service is needed to run this example. Captions and word timings are prepared inputs, not a transcript generated by this code.

## Run

Open a terminal in this example folder, where `package.json` is located:

```bash
node --version
npm ci
npm run check
npm test
```

If PowerShell blocks `npm.ps1`, use `npm.cmd` for the same commands.

Copy `.env.example` to `.env`: `Copy-Item .env.example .env` in PowerShell or `cp .env.example .env` on macOS/Linux. Open `.env` and put your key after `ZVID_API_KEY=`. Keep `MAX_RENDER_CREDITS=10` for this sample. The npm scripts load `.env` through Node's `--env-file` option. Keep this file private; it is ignored by Git.

```bash
npm start
```

Read the estimate and `out/validation.json`. The script stops on warnings, invalid data or an estimate above the maximum. Validation does not prove visual appearance or speech alignment.

When you accept the current estimate:

```bash
npm run render
```

This validates again, submits once, records the job ID, waits for `completed`, and downloads `out/timing-demo.mp4`. The script saves the attempt before submission and does not automatically retry a paid request. `out/run.json` prevents a second submission while an existing attempt is recorded.

If waiting or downloading fails, resume the same job:

```bash
npm run resume
```

If submission was interrupted before its ID was saved, check **Renders** at https://app.zvid.io. Find the matching `sync-timing-demo` job and recover its ID:

```bash
npm run resume -- --job-id YOUR_EXISTING_JOB_ID
```

Replace `YOUR_EXISTING_JOB_ID` with the actual ID. This command only reads the existing job and downloads its result. It never submits a render. A supplied ID must match an ID already saved in `out/run.json`. Do not clear the attempt and submit again while the earlier result is uncertain.

For a deliberately new render after reviewing the earlier job, move `out/` to a separately named archive, such as `out-first-run/`, before running `npm run render` again. Keep archives private and out of source control. Each new render spends credits. Do not edit the timing data and expect `resume` to update an existing job.

## What to inspect

Play the whole MP4 with sound. It should be 1280 × 720 at 30 fps and last 10 seconds. Check these cues:

| Project time | Expected result |
| --- | --- |
| 0.72s | `APPROVED` appears as the narrator says “approve”. |
| 2.72s | The second scene starts its 0.4-second fade as “Next” begins. |
| 3.76s | `WORDS + TIMES` appears as “words” is spoken. |
| 5.60s | The third scene starts its 0.4-second fade as “Then” begins. |
| 7.52s | `SAME TIMING RECORD` appears on “captions”. |
| 9.24s to 10s | Narration has ended; the last scene remains visible without replaying the audio. |

Caption highlights follow the supplied word times. Scene changes use the start of the fade as their cue; the next scene becomes fully visible 0.4 seconds later. All visible timing is sampled at the output frame rate, so subframe timestamps are represented by nearby frames.

## One timing record, three clocks

Edit `data/timing.json`, then run `npm run build` to create `out/request.json` and `out/timing-summary.json` without network access. The file's scene segments, word times and cue times use project seconds. `src/project.js` derives scene durations and local cue times:

```text
scene duration = next scene start - this scene start + outgoing overlap
local cue time = global cue time - scene start
output duration = sum(scene durations) - sum(overlaps)
```

The scene starts are 0, 2.72 and 5.60 seconds. With 0.4-second overlaps, scene durations are 3.12, 3.28 and 4.40 seconds. Total output length is `3.12 + 3.28 + 4.40 - 0.40 - 0.40 = 10`.

The cue at project time 3.76 belongs to the scene starting at 2.72, so its local `enterBegin` is 1.04. The word caption keeps its absolute `start: 3.76`.

Narration starts at project time zero and source time zero. The source is about 9.247 seconds; its playback window ends at 9.24 seconds. A shorter audio source can loop when placed in a longer window, so the example does not stretch its audio window to the ten-second picture duration.

## Change the sample

1. Finalize your recording first, and make its public HTTPS URL available to the renderer.
2. Review caption text and absolute word times against that exact recording. Transcription or alignment tools can help prepare them, but listening and correction remain your responsibility.
3. Set `audioEnd` to a verified usable source endpoint. This example starts audio at zero with speed 1; keep `audioEnd` within the actual recording to avoid looping.
4. Update the three contiguous segments, their headings, cues and captions. All caption words must match their caption text. End the final segment at `duration`.
5. Set `reviewed: true` only after that review. This is a local human-review flag, not a claim that the code can hear or fact-check the audio.
6. Run the offline checks, API validation and then an explicitly approved new render.

The three-segment layout, 30-second maximum, two-decimal timestamp precision, single-line text limits and warning stop are policies of this teaching example, not general Zvid limits. Zvid accepts other layouts and timing arrangements. The API applies your account's current limits.

Changing speech speed, leading silence or source trimming changes timing. Rebuild the caption and scene record after such changes. A nonzero source trim is a separate clock from placement on the output timeline; this small example does not implement trimming conversions.

## Files

- `data/timing.json`: the reviewed record and public narration URL.
- `src/project.js`: local checks and project compilation.
- `src/build.js`: offline request and timing-summary output.
- `src/index.js`, `src/helpers.js`: API validation, one submission, bounded tracking, recovery and download.
- `tests/`: offline behavior tests; no credentials, network or paid renders.
- `example.json`, dependency lockfile and license: reproducible source package metadata.

Generated `out/` files, `.env`, logs, node_modules and private account responses are not part of the source ZIP. Sample audio is linked, not bundled. Copy downloaded videos to storage you control if you need retention beyond your account's hosted-output lifetime.

## Troubleshooting

- **HTTP 401:** check that the API key is current and loaded from `.env`.
- **Validation warnings or credit limit:** inspect `out/validation.json`; fix the input or intentionally adjust your budget before rendering.
- **A previous submission is recorded:** resume it. Inspect dashboard Renders before considering another submission.
- **Failed render:** read `out/job.json` and `failedReason`. Resume reports the same failure; it does not fix or resubmit the job.
- **Captions drift:** compare the exact recording with `data/timing.json`. Updating narration without updating word timings will keep the old caption schedule.
- **An on-screen cue is late:** use scene-local visual time while keeping subtitle times absolute.
